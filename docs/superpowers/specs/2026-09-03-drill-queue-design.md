# 本轮练习队列（drill）—— 答错的词当场重练，不动熟练度

## 背景

现在的流程是「一个词一天只出现一次」：`/api/next` 发牌，`/api/review` 打分写库，
`last_reviewed` 变成今天，`app.py:148` 的分池条件就把它排除到明天。

问题是当天点了「模糊」或「不认识」的词，你**当天再也见不到它**，只能等 SRS 排到的
下一次（1 天或更久之后）。刚没记住的词恰恰是最该立刻重复的。

## 需求

点击卡片时按下表处理，新词旧词一视同仁，日语英语一视同仁：

**首次点击**（唯一一次影响熟练度，走现有 `/api/review`）：

| 点击 | 熟练度 | 临时计数 |
|---|---|---|
| 认识 | +1 | 不产生，直接通过 |
| 模糊 | 不变 | = 1 |
| 不认识 | −1 | = 2 |

产生临时计数的词会被**随机插回本轮学习**。

**之后每一次出现**（完全不调后端，熟练度冻结）：

| 点击 | 临时计数 |
|---|---|
| 认识 | −1，减到 0 就放走，本轮不再出现 |
| 模糊 / 不认识 | **不变**（这是有意的，不是遗漏） |

**逃生口**：连续 3 次没答对（只点模糊/不认识）就强制放走。点一次「认识」把连败
计数清零。没有这个口子，一个始终记不住的词会无限循环，`done` 永远不来。

被强制放走的词**熟练度也不变** —— 熟练度只由首次点击决定，这条没有例外。

「本轮」= 今天。跨天自动清空。

## 设计

### 一个简化：不需要记「哪些词已提交过 SRS」

一个词今天被 `/api/review` 打过分后 `last_reviewed` 就是今天，`app.py:148` 的分池条件
会排除它 —— **后端今天不可能再发同一个词**。所以：

> 当前这张卡是不是练习卡 ⟺ 这个词在不在 drill 表里

一个数据结构就够，不需要额外的 `scored` 集合。

### 状态

```js
// localStorage 键：tango_drill_<book>（和现有的 tango_extended_<book> 一个路数）
// { date: "2026-09-03", items: { [jp]: DrillItem } }
// date 不是今天 → 整个丢弃
DrillItem = {
  word:       { jp, kana, zh, section, level },  // 快照，重新出牌要用
                                                 // level 用 /api/review 返回的**新**等级，
                                                 // 不是 /api/next 给的旧等级（见下方「熟练度条」）
  kind:       "fuzzy" | "unknown",               // 初始档位，决定重现间隔
  remaining:  1 | 2,                             // 需求里的「临时计数」
  missStreak: 0,                                 // 连败次数，逃生口用
  countdown:  3,                                 // 还要过几张卡才重新出现
}
```

存 `word` 快照是必须的：练习卡由前端自己塞，后端不会再发这个词，没有别处能拿到内容。

### 出牌：改造 `loadNext()`（`index.html:448`）

```
1. drill[book] 所有项 countdown -= 1
2. 有 countdown <= 0 的 → 随机抽一个出牌，isDrillCard = true
3. 否则请求 /api/next
   ├─ 正常返回 → 出牌，isDrillCard = false
   └─ done ─┬─ drill 非空 → 取 countdown 最小的强行出牌
            └─ drill 空   → 才真正显示 done
```

第 3 步的 done 分支是必须的：**额度用完时不能直接 done，否则点过「模糊」的词会凭空
消失**，用户既没答对它、也再见不到它。

### 打分：改造 `score()`（`index.html:501`）

```
if (isFreeReview) → 现有逻辑，完全不参与 drill
if (isDrillCard):
    认识        → remaining--, missStreak = 0
    模糊/不认识 → missStreak++            // remaining 不变
    remaining <= 0 || missStreak >= 3 → 从 drill 删除（放走）
    否则 → countdown = 按 kind 重新随机
    存回 localStorage; loadNext(); return      // 不调任何接口
// 首次卡：走现有 /api/review（含斩词弹窗），然后
    模糊   → drill 建项 kind="fuzzy",   remaining=1, countdown=rand(4,6)
    不认识 → drill 建项 kind="unknown", remaining=2, countdown=rand(2,3)
    认识   → 不建项
```

重现间隔始终按 `kind` 算，不随 `remaining` 变 —— 「不认识」的词从头到尾密集重现
（隔 2~3 张），「模糊」的宽松些（隔 4~6 张）。

### 行为验算

| 过程 | 结果 |
|---|---|
| 模糊 → 认识 | 自然放走（练 1 次） |
| 模糊 → 模糊 → 模糊 → 模糊 | 逃生放走（3 次连败） |
| 不认识 → 认识 → 认识 | 自然放走（练 2 次） |
| 不认识 → 模糊 → 模糊 → 模糊 | 逃生放走 |
| 不认识 → 认识 → 模糊 → 模糊 → 模糊 | 逃生放走（认识清零连败，重新数 3 次） |

「不认识」最长练 5 次。

### 界面

练习卡必须有视觉标记，否则用户不知道为什么同一个词又来了、也不知道点了不算数。
在 `#section-tag` 位置显示 **「练习中 · 还需答对 N 次」**（N = `remaining`）。

**翻牌行为和普通卡完全一致**：正面只显示词，点「显示答案」才翻面。练习的价值在于
重新回忆一次，直接给答案就没意义了。

**熟练度条**显示首次点击**之后**的等级，并在整个练习过程中不动。注意这个值不能用
`/api/next` 返回的 `level`（那是打分前的旧值），要用 `/api/review` 响应里的 `level`
（`app.py:228` 返回的 `new_level`）—— 建 drill 项时就是在拿到这个响应之后，直接用它。
否则点了「不认识」的词，练习卡上会显示比实际高一级的熟练度。

### 纯函数边界

「选下一张牌」和「打分后更新计数」写成不碰 DOM 的纯函数（输入 drill 表 + 点击分数，
输出新的 drill 表 / 选中项）。前端目前没有测试基础设施，这样切分至少让这部分逻辑
将来可测，也便于本次手工核对。

## 涉及的改动点

**只有 `templates/index.html`。**

1. **JS 状态**：新增 `drill`（按 book 的练习表）、`isDrillCard`（当前牌来源）；新增
   `drillKey(book)` / `loadDrill()` / `saveDrill()`，跨天失效逻辑参照 `isExtendedToday()`
   （`index.html:420`）。
2. **JS 出牌**：`loadNext()` 按上面三步改造，done 分支加 drill 兜底。
3. **JS 打分**：`score()` 加练习卡分支，提前 return，不发请求。
4. **UI**：`#section-tag` 在练习卡上改显示「练习中 · 还需答对 N 次」。

## 不涉及的改动

- **不动后端**：`app.py`、`parser.py`、`scheduler.py`、`schema.sql` 一行不改，无迁移。
- **不动 SRS**：`next_review` / `level` / `review_count` 在首次点击时定死，练多少次都不变。
- **不动额度**：练习卡不写库，`today_new_count` / `today_review_count` 不受影响，
  进度行「新词 2/2 · 复习 70/70」照常。
- **不动自由复习**：`isFreeReview` 分支早返回，不参与 drill。
- **不动继续学习**：`extended` 只影响后端额度，drill 照常工作。
- **不动 `tests/test_srs_flow.py`**：它是纯后端模拟，drill 全在前端，该测试不受影响。

## 已知风险

1. **前端无自动化测试**。drill 逻辑靠手工验证；用纯函数边界降低将来补测试的成本。
2. **localStorage 可能写失败**（隐私模式、配额满）。所有读写包 `try/catch`，失败时
   降级为纯内存——刷新会丢练习队列，但不会白屏。
3. **词条内容当天被改**（编辑 `word.md`）时，drill 里是快照，会显示旧内容。跨天即消失，
   可接受。

## 测试关注点

- 首次点「认识」：熟练度 +1，不进练习队列，本轮不再出现。
- 首次点「模糊」：熟练度不变，隔 4~6 张重现；重现时点「认识」→ 放走。
- 首次点「不认识」：熟练度 −1，隔 2~3 张重现；需答对 2 次才放走。
- 练习卡上点任何分数**都不发 `/api/review` 请求**（开 Network 面板确认），熟练度条不变。
- 熟练度条显示的是**打分后**的等级：一个 level 3 的词点「不认识」，练习卡上应显示
  2 格而不是 3 格。
- 练习卡正面不直接给答案，翻牌流程与普通卡一致。
- 连续 3 次点模糊/不认识 → 放走；中间点一次认识 → 连败清零，需要重新连败 3 次。
- 额度用完时若练习队列非空，**先放完练习卡才显示 done**。
- 斩词弹窗只在首次点击时可能触发，练习卡上不会重复弹。
- 切到另一本再切回来，练习队列还在；跨天后自动清空。
- 自由复习模式下不产生练习卡。
